# Stable execution slots and local mutation

Noon now distinguishes three identities during the architecture migration:

- semantic identity (`SemanticNodeId`) belongs to the retained authoring/family graph;
- execution identity (`ExecutionSlotId`) is a generational runtime handle that survives unrelated insertion/removal;
- compiled/frame object slots are a stable compatibility view for the existing renderer while consumers migrate to execution identity.

`ExecutionSlotTable` uses tombstones plus a free list. Removing an object invalidates only its slot generation; unrelated slot IDs are unchanged. `SlottedSceneInstance` wraps the current `SceneInstance` and emits an `ExecutionDelta` that names the affected stable slots and timeline channels plus coarse structure/render/resource/hierarchy effects. This gives renderer/reactive/browser migrations a stable local impact contract before they stop consuming compiled/frame slot positions.

Structural and timeline `MutationTransaction`s no longer clone `SceneDefinition`. They build lightweight object/track identity metadata, validate the complete mutation sequence, then commit the already-preflighted patches. Heavy geometry and scene payloads therefore stay out of transaction staging.

Compiled timeline edits are channel-addressed. `CompiledScene` stores each `(object slot, property)` channel in its own sorted track vector behind `CompiledChannelKey`, with a stable track-ID locator index. Add/replace/remove therefore move entries only inside affected channels; unrelated track payloads do not relocate. Presence validation and dynamic-property recomputation also inspect only affected object channels. `CompiledPatchStats::unrelated_track_slots_shifted` is the deterministic zero-work contract for this boundary, while `dense_track_slots_shifted` now reports only movement inside an affected channel.

Runtime timeline edits are also channel-local. `SceneInstance` stores channel-addressed groups, and the event-driven scheduler keeps stable group slots plus a mutable event index so add/replace/remove-track operations relower only their old/new channels. The affected object is rebuilt from its compiled base and its channels are replayed in semantic property order before native reactive bindings are reapplied. Ordinary timeline edits therefore avoid both a full runtime-group rebuild and a full-scene seek. Initial scheduler lowering now consumes compiled channels directly instead of requiring a flattened cloned track vector.

Structural object edits are local as well. `CompiledScene` treats object-vector positions as stable append-only slots: removing an object tombstones its slot instead of shifting every later object and rewriting surviving track targets. Removal deletes only that object's channel entries and track locators, relowers only its runtime scheduler channels, marks one frame slot absent, and leaves every unrelated compiled/frame slot unchanged. Creation appends one compiled/frame slot and initializes only that slot. Neither operation performs a full runtime-group rebuild or full-scene seek.

Browser mutation batches preserve those locality guarantees end to end. `ScenePlayer` preflights the semantic transaction, compile-only constraints, and execution-slot mutation before committing any live state. Compatible structural and timeline batches commit through `SlottedSceneInstance` without cloning the semantic scene, recompiling the scene, rebuilding the runtime, or seeking the full playhead. Per-patch execution deltas are aggregated into one bounded `ExecutionDelta`, so a multi-mutation browser transaction names only the execution slots and channels it actually affected.

Structural execution identity now crosses the worker boundary directly. `ExecutionDeltaEncoder` consumes the authoritative runtime `ExecutionSlotId` values instead of allocating a second engine-side identity space. Ordinary removals are encoded as bounded `removed` slot IDs rather than forcing a compact full snapshot, while creates append one object with its new stable slot. `ExecutionFrameMirror` retires removed entries in place and appends creates, so later frame positions are not shifted and transport order remains aligned with source/painter order. Full snapshots remain only for initialization, explicit resynchronization, incompatible scene replacement, or sequence/session recovery.

Renderer preparation follows the same tombstone contract. A structural removal keeps its packed primitive slot and painter batch stable, writes zero opacity into only that packed instance, and marks only that instance range dirty; vector-path removals also update the corresponding mega-mesh instance attributes without repacking unrelated geometry. Tail-appended objects, including new vector-path resources, extend packed storage and source-order render batches locally. New path meshes allocate one local arena chunk and append only their mega-index suffix, so ordinary structural creation no longer falls back to full renderer preparation.

New structural objects deliberately append instead of reusing retired middle compiled/frame/render slots. Reusing a middle position would silently change source/painter order. Reclamation is therefore an explicit maintenance barrier: the current live semantic scene is recompiled in source/painter order, durable `ExecutionSlotId`s are preserved, compatibility frame rows are compacted, and a monotonically increasing layout generation invalidates stale `FrameSlotId`s. The rebuilt runtime leaves `FrameChanges::all()` pending, so renderer preparation and worker transport perform an intentional full resynchronization at the checkpoint rather than observing hidden renumbering during an ordinary live edit. `RetiredSlotCompactionPolicy` is only a recommendation heuristic; compaction is never triggered implicitly by the mutation fast path.

The regression suite exercises 100,000 execution slots, stale-generation rejection, atomic generation-exhaustion failure, stable compiled object removal, single-channel timeline deltas, a 10,000-track local compiler edit, cross-object track replacement, a 100,000-channel scheduler relower, a 10,000-channel live runtime timeline edit, and a 100,000-object structural live-edit case. A separate 10,000-track storage regression records the address of an unrelated compiled track payload across a local channel edit and requires that address to remain unchanged. Browser transaction coverage removes one object from a 100,000-object scene and requires zero semantic-scene clones, zero runtime rebuilds, zero full seeks, stable unrelated execution identity, and a one-slot execution delta. Transport coverage requires that removal to remain a non-snapshot one-slot delta. Renderer coverage removes one of 100,000 analytic objects and requires one retired packed instance, one dirty upload range, and zero full preparation rebuilds.

## #58 completion boundary

The normal compiler/runtime/browser/worker/render mutation path no longer depends on dense object renumbering, global track-vector movement, semantic-scene cloning, recompilation, full runtime-group rebuilds, full-scene seeks, structural transport snapshots, or full renderer preparation for structural edits. Retired compatibility capacity is reclaimable through the explicit generation/order-aware compaction barrier described above, while durable execution identities remain stable. Structural creation of new vector-path resources is local as of #196.

Compaction is intentionally the one stop-the-world maintenance operation: it is outside the latency-sensitive mutation path, rebuilds the compact compatibility runtime once, restores the current playhead, and forces one renderer/transport snapshot. This makes the cost observable and opt-in instead of allowing tombstone reclamation to silently perturb source/painter order. The event-driven scheduler from #52 remains the timeline algorithm; channel-addressed storage feeds its existing local relowering path rather than replacing it.
